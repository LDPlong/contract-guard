# 画布修复指令单：03 与 07 的三档处理

> 目标文件：`https://ardot.tencent.com/file/747625067755365`
> 前置条件：会话能调用 `mcp__ardot__batch_edit`（连不上的话先看文末）。
> 背景：02 审查台的三档已经从「左侧竖色条」改成「数字下方 2px 彩线」，03 和 07 还是旧写法，需要同步。

## A · 03 移动端 · 结论页（12 个操作，可一次执行）

节点全在 `2:231`（结论卡）里，三组分别为 高 `2:243` / 中 `2:248` / 低 `2:253`。每组的改法完全一样：把色条移进数值组、改成 2px 横线、标签提到 11.5 并加深。

```javascript
M("2:244", "2:245", 1)
U("2:244", {width:"fill_container", height:2})
U("2:245", {gap:4})
U("2:247", {fontSize:11.5, fill:"#454B54"})
M("2:249", "2:250", 1)
U("2:249", {width:"fill_container", height:2})
U("2:250", {gap:4})
U("2:252", {fontSize:11.5, fill:"#454B54"})
M("2:254", "2:255", 1)
U("2:254", {width:"fill_container", height:2})
U("2:255", {gap:4})
U("2:257", {fontSize:11.5, fill:"#454B54"})
```

| 节点 | 名称 | 作用 |
| --- | --- | --- |
| `2:243 / 244 / 245 / 246 / 247` | 高 · 色条 · 组 · 数 · 名 | 高风险那一组 |
| `2:248 / 249 / 250 / 251 / 252` | 中 · 色条 · 组 · 数 · 名 | 中风险 |
| `2:253 / 254 / 255 / 256 / 257` | 低 · 色条 · 组 · 数 · 名 | 低风险 |

数字字号（`2:246 / 251 / 256` = 15）保持不动 —— 移动端本来就该比桌面端小，02 是 22，这里是 15，是有意的响应式缩放。

## B · 07 审查台 · 答疑浮层（3 个操作，整体重建）

07 是 02 的**旧副本**（在 02 改之前复制的），所以它同时欠了三笔账：两条通高分隔线、18px 的旧数字、竖色条。逐个改要十几次操作，还要先摸出副本内部的节点 ID。

**直接重建更省事，且不会漏**：删掉旧的 07，用现在的 02 重新复制一份，再把描图纸浮层实例放回去。

```javascript
D("5:35")
n7=C("2:5", "0:1", {name:"07 审查台 · 答疑浮层（描图纸）", x:3100, y:150})
p7=I(n7, {type:"ref", ref:"5:266", name:"答疑浮层 · 描图纸实例", x:1036, y:476, width:380, height:400, layoutPositioning:"ABSOLUTE"})
```

- `2:5` = 02 审查台（已经是对的）
- `5:266` = 组件 `浮层材质 / 描图纸`
- 浮层位置按 02 的坐标系：右 24、下 24、380×400
- 画布上的「标注07」文字（`5:193`）是独立节点，不受影响

## 验证

注意：B 段执行后 `5:35` 已经不存在了，新节点由 `C()` 生成，ID 是新的。**用它返回的 ID 截图**，不要照抄 `5:35`。

```javascript
capture_screenshot(nodeIds: ["2:6", n7])
```

如果拿不到 `n7` 的具体值，就按名称截图或整页截。检查三点：

1. 03 的三档：标签在上、数字 15px 在下、数字下方一条彩色短横线，宽度跟随标签。
2. 03 卡片内没有多出来的空隙，底部按钮仍在原位。
3. 07 的结论尺与 02 完全一致（无竖分隔线、数字 22、彩线），右侧浮层仍在右下角、没有跑偏。
   07 是 02 的**完整副本**（同为 1440×900），所以浮层的 1036 / 476 可以直接沿用；截图里如果看到浮层偏出边界，说明复制时尺寸没跟上，按当次实际尺寸重算即可。

## 如果工具还是不在

`mcp__ardot__*` 没挂上时，任何 batch_edit 都会报 tool not found。**先判断是哪一层的问题：**

**① 模式不对（最常见）**
画布工具是随「设计模式」挂载的。会话一旦切到 Agent / Craft 模式，这组工具就会整体消失，且**不会自动恢复**。判断方法：看会话里是不是反复出现 “You are now in Agent mode”。
解法：切回设计模式，或从设计画布入口重新发起对话。

**② 插件被禁用**
去「专家技能连接器」检查设计画布是否启用。启用后**必须新开会话**才生效。

**③ 换会话也没用**
如果新会话、设计模式都试过仍然没有，说明这个环境里画布能力整体没挂上，不是操作问题。此时：
- 画布内容不会丢（云端文件仍在），只是暂时不能编辑；
- 把本指令单留着，等能连上时整段粘进去执行。

重试同一个调用没有意义，报错永远是 tool not found。
